<objective>
Verify Strapi connection and wire Homepage to CMS with static generation (ISG).

Purpose: Establish the CMS integration pattern using Incremental Static Generation - CMS data fetched at BUILD TIME only, resulting in fully static pages with no runtime CMS dependency.
Output: Homepage statically generated with Strapi data baked in at build time.
</objective>

@app/[locale]/page.tsx

**Key Strapi functions already exist:**
- `getHomepage(locale)` - fetches hero, brand logos, gallery images, key projects, space section, crew area
- `getStrapiImageUrl(image)` - converts Strapi image to full URL
- Types: `StrapiHomepage`, `StrapiKeyProject`, `StrapiSpaceSection`, `StrapiCrewArea`

**Environment:**
- Strapi Cloud URL already in code: `https://fantastic-attraction-7b2626fe03.strapiapp.com`
- API token env var: `STRAPI_API_TOKEN` (needs to be set)

**ISG Pattern:**
1. Server Component fetches Strapi data at BUILD TIME
2. Data is baked into static HTML
3. No runtime CMS calls - pages are fully static
4. Content updates require rebuild (or ISR revalidation if configured)
5. Dev fallback only - for local dev when Strapi might not be accessible
</context>

       ```typescript
         const { locale } = await params;

         // Data is now baked into static HTML
       }
       ```

    3. Create helper functions to transform Strapi data to component props:

       - In production build, Strapi MUST be available (fail build if not)
       - This ensures content is always present in production

    5. Handle interactive sections:

       - TrustedBySection, GallerySection may need "use client" wrappers
       - Pass static data from server to client components as props
