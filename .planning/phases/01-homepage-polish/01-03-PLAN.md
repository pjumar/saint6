    <task>
      <number>2</number>
      <title>Inspect &amp; Optimize GSAP Animations</title>
      <description>
        Review and test TrustedBySection GSAP animation behavior:

        Analysis steps:
        1. Read app/components/trusted-by-section/TrustedBySection.tsx
           - Understand animation timeline and trigger conditions
           - Identify what animates (infinite scroll logos? carousel?)
           - Check animation settings: duration, easing, delays

        2. Understand current behavior:
           - When does animation run? (on load? on scroll? on resize?)
           - What's the viewport behavior? (mobile only? desktop only? both?)
           - Are there resize listeners that recalculate? (potential jank source)
           - Does animation loop smoothly?

        3. Test animation visually:
           - At mobile (375px): Does animation work as intended?
           - At tablet (768px): Does animation behavior change?
           - At desktop (1440px): Is animation disabled or different?
           - Scroll through section multiple times: Is animation consistent?
           - Open DevTools Performance tab: Record animation, check for jank/dropped frames

        4. Check for issues noted in CONCERNS.md:
           - Animation recalculates on every window resize (potential jank)
           - Logos array is duplicated for animation (2x DOM elements)
           - No debounce on resize listener (fires too frequently)
           - Compare animation smoothness to design intent

        5. Verify animation cleanup:
           - Does useEffect cleanup properly remove listeners?
           - No memory leaks (test by navigating away and back)
           - No lingering timelines or intervals?

        Based on findings, decide:
        - Is animation matching design? If yes, no changes needed.
        - Is animation causing jank? If yes, optimize (debounce resize, precompute dimensions)
        - Is animation not matching intent? If yes, adjust timing/easing/behavior
      </description>
      <acceptance_criteria>
        - [ ] TrustedBySection animation thoroughly tested at multiple breakpoints
        - [ ] Animation performs smoothly (no dropped frames in DevTools)
        - [ ] Animation matches design intent/specification
        - [ ] Resize behavior is smooth (no jank when resizing browser)
        - [ ] Memory leaks checked (listeners properly cleaned up)
        - [ ] Mobile vs desktop behavior verified (matches design)
        - [ ] Animation cleanup in useEffect confirmed working
        - [ ] Any performance issues identified and documented
      </acceptance_criteria>
      <checkpoint>
        DevTools Performance recording showing smooth animation frames (60fps target)
      </checkpoint>

      <description>
        Verify homepage performance is acceptable:

        Performance metrics to check:
        1. Load time:
           - Time to First Paint (FCP)
           - Largest Contentful Paint (LCP)
           - Cumulative Layout Shift (CLS)
           - Total Blocking Time (TBT)

        2. Runtime performance:
           - FPS during scroll (target: 60fps)
           - FPS during animations (target: 60fps)
           - CPU usage while idle (should be low)
           - Memory usage (no memory leaks)

        Testing procedure:
        1. Open browser DevTools → Performance/Lighthouse tab
        2. Run Lighthouse audit (mobile and desktop)
        3. Note scores and recommendations:
           - Performance score (target: 80+)
           - any warnings about images, fonts, CSS, JS

        4. Manual performance testing:
           - Open DevTools → Performance tab
           - Record 5-10 second interaction:
             - Page load
             - Scroll down full page
             - Open mobile menu (if testing mobile)
             - Resize browser window
           - Analyze recording: FPS graph should be high, no long tasks

        5. Check for common performance issues:
           - Large images not optimized (use Next.js Image component)
           - Missing lazy loading on below-fold content
           - Unused CSS or JavaScript
           - Long Main Thread tasks
           - Memory leaks from animations

        If issues found, document them. Minor issues (performance score 70-80) don't block Phase 1, but should be tracked for Phase 7 optimization.
      </description>
